# 项目边界与路线图

目的：以学习为主，功能边界明确后逐步追求极小体积；与其他操作系统项目分离。

## 当前里程碑：可启动、可观察

已完成：Rust 入口、装载自检、串口日志、帧缓冲文字、内存地图统计、混合 ISO、QEMU UEFI / BIOS 和 Ventoy Memdisk 启动测试。实机显示仍需 Jeremy 在 ShadowSecretary 验证。

## 下一里程碑：可交互

先验证真实机器的屏幕，再建立异常 / 中断处理与计时基础，确认目标机器键盘连接方式并实现所需驱动，最后提供简单命令交互。不能把 QEMU 内的某一种键盘驱动当成 Mac 实机兼容的证明。

## 后续候选核心能力（边界待确定）

物理页分配与虚拟内存 → 任务调度 → 用户态隔离与系统调用 → 用户程序装载 → 基础文件系统与终端工具。

这是一条学习顺序，不代表每项实现已经确定。网络、桌面、音频、广泛硬件兼容不自动纳入。添加功能前记录验收条件和预计成本，完成后测量真实增量。

## 如何衡量“小”

分开记录：发布 ELF、完整系统文件、引导 ISO、运行内存。比较其他系统时必须同时列出架构、功能、引导依赖、压缩方式和调试信息是否移除。

现有 32 KiB 内核预算是第一阶段的审查门槛，超限时先找原因；确有必要的功能可以附带依据调整预算。禁止为通过预算删掉必需功能或安全检查，也不靠修改测量口径制造更小的数字。
